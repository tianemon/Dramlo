# Dramlo 扩展库与导入规范草案

本方案定义扩展的管理、交付和注册。节点执行复用 Dramlo 的项目、资产和任务接口。产品范围与验收状态以[产品基线](studio-product-goal.md)为准。以下为设计，待样例跑通后冻结首版格式。

## 扩展库

在全局导航提供「扩展库」。默认可按来源、能力和状态筛选。每个扩展只有一条主记录，详情列出它提供的节点、Skill、工具，以及在哪些项目中使用。

| 来源 | 登记方式 | 管理方式 |
| --- | --- | --- |
| 内置 | 随 Dramlo 版本发布，来源由发行包登记 | 可查看版本和说明，可停用非核心能力。随 Dramlo 更新。 |
| 自定义 | 用户或 Agent 创建的本地扩展 | 本地开发目录可重新校验，正式版本打包安装，可导出分享。 |
| 外部导入 | 从共享扩展包或已有工具配置登记 | 显示实际来源和安装版本，可更新、停用、卸载。 |

来源由安装入口记录。包内声明的作者仅用于展示，不能把自己标为内置。安装范围和启用范围独立，首版支持装到本机、按项目启用第三方扩展。详情展示权限、版本兼容性、最后一次错误和受影响的节点。缺少依赖、版本不兼容、待启用和运行错误分别提示。

## 节点、工具和界面

一个扩展可包含多个贡献项。每项用稳定 ID 注册到 Dramlo 后端。画布添加菜单、检查器和 MCP 共用同一份节点描述。Agent 可通过稳定接口列出节点、查看端口与字段说明、创建节点、连线和运行。独立于画布使用的工具可同时发布到 MCP 工具清单，由扩展明确声明。

- 节点声明输入、输出、参数、执行方式和面向用户的字段说明。视频、图片、音频和文本等端口可校验连接。素材以项目资产 ID 引用。
- 执行器可绑定 Dramlo 已有能力、某个 ComfyUI 工作流或已登记的外部 MCP 工具。Skill 提供创作规则和可选节点组合，组合中的执行步骤绑定具体能力。
- 首版开放节点卡片、右侧检查器和确认弹窗。宿主提供文本、数值、单选、素材选择、媒体预览、进度和错误组件，插件声明组件和动作的对应关系。独立页面和工具栏位置可沿用这套贡献机制，按具体需求再开放。
- 插件请求读写项目、登记素材或运行任务时，由 Dramlo 校验权限和项目修订。外部工具的实际进程权限另行处理。进程隔离能减少崩溃影响，其文件和网络访问取决于运行环境。安装未知执行器需要用户确认来源和权限。

## 节点参数与工作流映射

原生 Web 支持声明扩展参数和端口，并为单个节点保存覆盖值。使用 `studio_extension_preview` 校验清单，安装并按项目启用后创建节点。用 `studio_describe_extension_node` 查看参数、覆盖值和端口，用 `studio_update_extension_node` 局部修改参数，传 `null` 清除该项覆盖。修改后重新预检，界面也可逐项编辑。

ComfyUI 视频节点把参数绑定到 API 图中的标量字段。例如 `{"key":"steps","label":"采样步数","type":"integer","min":1,"max":100,"default":24,"target":{"nodeId":"23:7","field":"steps"}}`。模型权重使用 `type: "model"`，填写 ComfyUI 枚举的相对权重文件名。查询节点时传 `includeChoices: true` 可向所属 ComfyUI 读取模型和枚举选项。未填写默认值或覆盖值时，保留工作流原值。

ComfyUI 视频节点的图片端口按声明顺序对应普通参考图。使用连线时须接齐已声明的端口，首帧和尾帧仍按生成计划提供。尾帧提取节点支持一个视频输入和一个图像输出。MCP 扩展可声明工具参数，以及已支持的图像输出。旧清单继续使用原来的端口和行为。

- 派生镜头节点从分镜读取时长、提示词、首尾帧和所选生成配置。自由生成节点及扩展实例保存自身参数。画布同步重建派生结构时，保留节点专有的参数、可编辑连线和已生成资产。升级老项目时兼容只存在于旧节点的有效设置。界面、MCP 和生成队列共用配置优先级，提交前返回实际生效的配置。
- 扩展清单声明参数类型、默认值、范围和枚举，以及执行器支持的输入输出端口。界面和 MCP 使用同一份定义创建、读取和更新节点实例，校验参数与连线。Agent 可用清单创建自定义类型，沿用扩展库的预检、版本管理和项目启用流程。执行器未实现的能力不得靠声明启用。
- ComfyUI 扩展可把一个节点参数绑定到工作流的具体输入字段。参数覆盖独立保存，预检时应用到工作流副本。权重与采样器等枚举从目标 ComfyUI 的节点元数据读取。只允许覆盖已声明且类型相符的字段，禁止覆盖媒体连线或与现有映射重复。参数改动纳入生成计划版本校验。

验收时为两镜选择不同视频工作流，修改其中一镜后重建画布并重开项目，核对界面和 MCP 预检选用同一配置。再用一个自定义 ComfyUI 节点分别设置采样参数和权重，核对预检应用了覆盖值，原工作流与另一实例保持原值。

## 外部 Agent 接入与使用范围

短剧专用 Skill 和外部 MCP 上游只在 Dramlo 扩展库登记一次。用户在所用 Agent 里配置一个 Dramlo MCP 入口，就能按项目使用 Dramlo 的扩展。连接配置由用户授权写入客户端。Dramlo 无须改动客户端原有的 Skill、MCP、系统提示、模型或项目配置。支持项目级 MCP 配置的客户端可把入口设为项目级；全局配置的客户端也能选择只在制作任务中使用该入口。

| 能力 | Dramlo 集中维护 | 外部 Agent 怎样用 |
| --- | --- | --- |
| 创作 Skill | 正文、参考资料、来源、版本和启用项目 | 用现有 Skill 查询和读取工具获得任务所需正文与资料。按 ID、来源和修订区分同名 Skill。可以临时使用于当前任务。 |
| 外部 MCP 工具 | 上游连接、凭据引用、工具说明、启用项目和发布范围 | 通过同一个 Dramlo MCP 发现和调用 Dramlo 已经发布的能力。Dramlo 负责检查项目权限、向上游发请求和回报结果。 |
| 画布节点 | 节点定义、端口、表单、执行器和版本 | 用画布节点目录发现节点。通过 MCP 创建、连线、运行和查询结果，与人工界面共用项目状态。 |

### 按项目发现和调用

1. Agent 通过 Dramlo MCP 读取当前指南，明确本次要操作的项目。项目级调用提交明确的项目 ID，宿主每次核验项目启用状态、可用能力和授权。工程、写作和素材生成以当前项目为边界。
2. 工作台通用工具保持稳定。项目级 Skill、节点和工具由目录按需发现，返回用途、输入输出和来源。建议首版通过稳定的项目级调用入口访问扩展工具，避免客户端全局工具清单持续膨胀，也避免多个 Agent 同时处理不同项目时互相改变可见范围。需要原生 MCP 工具发现的扩展，可显式发布具备独立命名空间的工具；调用时同样核验项目。工具集合变化沿用刷新通知。
3. Agent 按需读取 Skill 正文及引用资料。正文参与当前短剧任务。扩展声明中涉及付费生成、项目写入或需要人工确认的步骤，由宿主执行时按用户授权检查。上游工具的说明、结果和 Skill 内容用于提供工作信息。
4. 用户停用或更新扩展后，目录反映新状态。已经打开旧目录的客户端调用时重新校验，版本不兼容则提示重读。已运行的任务保留当时版本和结果，按原任务状态收尾。一个 Agent 改当前项目，不会改变另一个 Agent 正在使用的项目范围。

### 安装和运行边界

- 管理库保存一份上游配置，凭据由 Dramlo 管理。客户端获得 Dramlo 连接及调用结果，外部 Agent 的自身供应商和工具权限由客户端管理。
- 项目资产优先通过资产引用传递。第三方结果由 Dramlo 登记并标注来源、版本和任务。外部工具故障时报告具体扩展及状态，其他工具照常可用。
- 首轮用两个隔离客户端验收。它们各自只连接 Dramlo，能读取同一份自定义分镜 Skill，并调用一项已启用的上游工具。停用一个项目里的扩展后，该项目无法再调用，另一个项目继续可用。前后对比客户端自己的 Skill 和原有 MCP 配置。

## 导入与更新

首版提供本地入口，无需公共市场。载体包括 Dramlo 扩展包、本地开发目录，以及通过现有入口登记的 ComfyUI API JSON、外部 MCP 配置和创作 Skill。原始导入项在 Dramlo 内用同样的扩展登记和节点描述呈现。

正式扩展包先用 ZIP 加根目录清单。清单至少包含格式版本、插件 ID、版本、宿主兼容范围、贡献项、依赖、请求权限和入口。插件 ID 建议带作者命名空间。导出的包应包含可分享的描述、工作流和资源，相应连接密钥与本机绝对路径由安装方重新配置。

1. **预检**。识别格式，检查文件范围、ID 冲突、依赖、版本和端口映射。列出将新增的节点、工具、界面位置和请求权限。预检不启动执行器。
2. **安装**。在隔离目录校验完整后登记版本。失败保留原版本。来自不同来源的同 ID 扩展提示冲突，由用户决定如何处理。
3. **启用**。确认后发布到指定项目的画布与 MCP。工具清单变化时复用现有刷新通知。管理页和 MCP 调用相同的预检、安装、启停及状态查询机制。
4. **更新与停用**。项目保存节点类型及其使用的版本。升级前显示受影响节点。有破坏性变化时，通过显式迁移更新项目。停用或缺包时保留节点、参数、连线、历史产物和版本信息，并提示如何恢复。

公共目录以后可以提供搜索、来源校验和版本发现，复用相同的本地安装接口。用户可先通过导出包互相分享，也可让 Agent 按模板创建包。

## 第一轮验收

1. 把现有「提取视频尾帧」登记为内置能力。Agent 创建节点并接上视频，用户在画布运行，结果能连到下一镜首帧。
2. 让 Agent 按公开模板创建一个本地自定义节点，用开发目录预检，再导出成包。在隔离项目重新导入，界面能列出来源、版本和节点贡献，Agent 沿用原 MCP 发现并操作。将一条既有 ComfyUI 工作流封装成第二个样例，验证长任务和素材回收。
3. 停用扩展并重开项目，确认保存的节点、连线和旧素材仍可查看。恢复扩展后能重新执行。用一个不兼容的升级包验证预检能阻止替换。
4. 发放一套面向人和 Agent 的节点模板、组件清单、清单格式和校验命令。然后用进程外的第三方 MCP 工具验证新的执行来源。

## 内置尾帧节点试点

在 Web 画布右键添加「提取视频尾帧」，把分镜成片或自由视频节点的输出接到视频端口，点击「运行」。也可从 MCP 创建节点时指定项目视频素材 ID。节点输出登记为项目图片。把输出接到 H3 自由视频节点的首帧端口后，生成时使用连线输出；若上游换片，先重跑尾帧节点。执行需要配置本机 FFmpeg。

Agent 用 `studio_list_node_types` 查看可用节点，以 `studio_add_extension_node`、`studio_connect_extension_node` 和 `studio_run_extension_node` 改画布和运行。每次写入使用最近的项目修订。

## 当前可用的扩展库试点

在 Web 左栏打开「扩展库」。这里区分内置节点与自定义清单，并可预检、安装和导出 JSON。自定义扩展安装后按项目启用，节点保存时记录版本。停用时保留原节点、连线和产物。

清单模板提供尾帧提取与 ComfyUI 视频两种执行器。ComfyUI 清单引用已导入的视频配置 ID。启用后在画布添加节点，选分镜和输入方式，预检通过后在现有制作批次核对并确认。成功的视频回到原节点与项目素材库。Agent 可用 `studio_prepare_comfy_node` 预检，并沿用原制作批次工具确认和查状态。

### 导入、分享与开发

可以直接导入本地 JSON，或导入 ZIP。ZIP 根目录须只有一个 `extension.json`，其中可放一条清单，或用 `{"formatVersion":1,"extensions":[...]}` 组织最多 16 条。一个包整体预检并安装。扩展库提供模板和单项导出。清单里的 ComfyUI 配置 ID、MCP 连接 ID 由安装方按本机配置填写。ZIP 只携带声明，导出时不带上游启动命令、参数或接入凭据。

### 接入第三方 MCP 工具

1. 在扩展库的「管理本机 MCP」登记 stdio 可执行文件、参数、连接 ID 和允许的工具名，确认信任后保存。进程拥有当前用户的系统权限。Dramlo 不传递桥接令牌和当前进程的其他业务环境变量。连接与清单分开登记。
2. 导入以 `studio.mcp` 为执行器的清单，填写 `providerId` 和 `tool`，按项目启用。需要在画布产出图片时加 `"outputKind":"image"`。节点保存工具结果；声明图片输出时，Dramlo 登记工具返回的第一张受支持图片，并提供图片端口。
3. Agent 继续使用原 Dramlo MCP。先用 `studio_extension_library` 查看所选项目的扩展，再用 `studio_describe_extension_tool` 读取真实工具参数，以 `studio_call_extension_tool` 直接调用，或用 `studio_run_extension_node` 运行画布节点。停用、卸载或撤销连接会阻止新的调用。调用超时或结果未能保存时，先核对上游状态，再决定是否重试。

当前实现支持本地 stdio、声明式清单及 Dramlo 现有节点组件。目录热加载、自定义前端组件、远程 MCP 传输和公共市场属于后续设计。

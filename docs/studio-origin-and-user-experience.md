# 为什么做 Dramlo｜使用经历与宣传素材

这份记录来自 Amon 实际尝试短剧工作台、内置 Agent 和本机 ComfyUI 的经历。每条保留当时的问题、造成的影响和对应的解决思路，供日后写宣传视频脚本或选演示场景。产品范围、实现和验收状态见[产品目标与验收基线](studio-product-goal.md)。

## 1. 视频出来以后，才发现故事拍偏了

- **实际体验**。在试用过的一些工作台中，输入一句提示词或一段剧情大纲，生成的剧本和分镜直接填进许多框。想了解剧情得逐条点开，很难连着读、核对故事是否偏离最初设想。逐镜查看太费劲，容易觉得大差不差就继续生成，最后才发现出来的东西和自己想要的完全不同。
- **解决思路**。在自己熟悉的 Agent 里聊剧情、修改大纲、通读完整剧本，确认后再拆分镜。确认稿与分镜进入同一个 Dramlo 项目，镜头能回查对应场次。故事改动时先指出哪些场和镜头需要复核，生成前保留人工确认。
- **宣传切入点**。演示同一个剧情如何从聊天里反复修改到确认，再回到画布核对某一镜的剧情依据。观众能看到创作者在生成前做了哪些决定。

## 2. 已经有常用 Agent，进工作台还要再配一套

- **实际体验**。试用内置 Agent 时，常要另配模型和 API。已有的订阅或 Token Plan 能否沿用取决于入口和供应商，直接调用 API 可能另计费用。按 Amon 当时遇到的配置和用量条件，实际选择也比较少，往往只考虑 DeepSeek，有时会考虑小米 MiMo。
- **解决思路**。通过 MCP 让用户沿用自己的 Agent、习惯和套餐。工作台继续支持已配置的生成服务，用户也可使用自己的 API 额度、本地 ComfyUI，或把常用 Agent 平台在其套餐和能力范围内生成的图导入画布。
- **宣传切入点**。从一个已在使用的 Agent 会话打开 Dramlo 项目，把会话里产出的角色图变成画布素材。演示只说明当次实际使用的能力和费用入口。

## 3. 内置 Agent 有画布工具，跨软件的任务还是要来回切

- **实际体验**。Amon 用过的内置 Agent 可以根据内部 Skill 操作画布，但上下文管理和可调用工具的范围，与自己习惯的通用 Agent 有差距。创作还涉及读本机资料、看已有图片、找工作流和管理文件，把这些事拆到不同入口做，就得反复交代背景。
- **解决思路**。Dramlo 通过 MCP 提供项目、设置、画布、任务和素材能力，CLI 作为本机脚本接口方向。创作 Skill 留在 Dramlo，外部 Agent 按需读取，继续沿用自己的技能体系。想同时看对话和操作结果，可以用系统分屏把 Agent 和 Dramlo 并排打开。
- **宣传切入点**。在同一段对话里找本地素材、改镜头、查看结果，再在并排的画布里手动微调，让下次 Agent 读取用到新值。

## 4. 接 ComfyUI 的精力花在导出、导入和猜配置上

- **实际体验**。网关列表里的预设看得见，本机却未必有对应权重或节点。本机用的是不同权重，还需要把自己的工作流另导出为 API JSON 再导入。有的导入项名称不直观，生图工作流也曾被识别成视频。配置、改名和查找都费劲。
- **解决思路**。发现本机可用的 ComfyUI 安装和工作流，让用户决定登记哪些实例。Agent 按实例读取、校验和导入兼容工作流，保留原图的权重配置，提交前说明支持的输入和缺项。设置页和工具说明都给出清楚的字段提示。
- **宣传切入点**。从已经在用的本地 ComfyUI 找到一条工作流，把它接到 Dramlo 的视频设置，再展示一次不产生生成任务的预检。

## 5. 连上上一帧，动作还是可能接错

- **实际体验**。机器人续拍时，把前一镜尾图当普通参考图会让画面看起来相似，下一段却重复关舱盖。改为使用前一镜选中成片的真实尾帧作为下一镜首帧后，Amon 确认画面接上了。另遇到过竖版仍出横版或画面被压扁。
- **解决思路**。按镜头需要区分角色与场景参考、首帧、尾帧。连续动作从已选原片取真实尾帧，下一镜动作从当时状态写起。换场可硬切。核对竖版时，同时看实际提交的 API 图绑定与产物像素尺寸。批量一次确认、逐镜串行，遇到失败或结果未知就停，已保存候选继续留在原镜头。
- **宣传切入点**。并排展示重复关舱盖的试片和衔接后的试片，并用第三镜换场说明什么时候应该断开尾帧依赖。

## 6. 做到一半，频繁找入口、找配置、找原片

- **实际体验**。进项目或设置时，全局导航会消失，进入项目也曾找不到第一步的剧本入口。语言模型、生图和视频等先前配置曾在新入口里看不到。首次让外部 Agent 接入时，又遇到令牌和配置说明难拼起来、工作台关闭后难以用官方入口启动等问题。
- **解决思路**。固定全局导航，在项目内保留完整剧本入口。显示当前生效的配置。首次把接入说明交给 Agent，此后在同一 MCP 查询在线指南和 Skill。生成结果自动回到原镜头和项目素材库，能预览、选用、打开本机原片位置，重开后能看懂任务停在哪。
- **宣传切入点**。从一个已有项目开始，让观众看到确认稿、镜头候选和本机原片之间怎么来回查，接着演示暂停后继续制作。

## 对外表达草案

> 我做 Dramlo，是因为视频都生成完了，我才发现，我还没机会好好看完自己要拍的故事。现在我可以在熟悉的 Agent 里把剧情聊清楚、把剧本读一遍，再交给 Dramlo 拆镜头、接工作流和收素材。故事按我确认的版本往下拍，途中我随时能接手。

后续遇到新的例子，在对应条目下补具体操作、影响和可复现的演示素材。视频录制时，用当次实测结果支撑产品能力。

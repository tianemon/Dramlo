# 内置 Agent 职责盘点与全面 MCP 化

更新于 2026-11-20（北京时间）。产品决策已确定为完整移除内置 Agent 运行时。Dramlo 负责项目状态、制作工具、媒体处理、任务执行和持久化，外部 Agent 负责理解、创作、视觉判断和计划。用户依旧可以手动制作。本文按 Fork 本地代码盘点，源码核对与隔离联调的结论不作为真实 H3 生成验收。

## 普通画布 Agent 怎么工作

1. Studio 页面挂载 AgentChat。它收集消息、附件、当前选中节点和自主度，记录项目聊天历史，为本轮创建 AbortController，订阅计划、工具、进度和错误事件。选区文字编辑有单独快路径。入口在 [StudioView.vue](../src/views/StudioView.vue) 和 [AgentChat.vue](../src/components/canvas/AgentChat.vue)。
2. runAgentTurn 读取 Pinia 当前项目，构造模型上下文。它提供项目与画幅、当前图像和视频配置的摘要、剧本确认状态、缺失产物计数和节点清单。根据请求选择性加上剧本片段、人物、场景、分镜及画布明细，补入真实选中节点、附件、近期对话、项目或全局记忆和所选 Skill。图片内容由独立看图工具实际读取；节点名称和资产 ID 只提供索引。见 [agent.ts](../src/services/canvas/agent.ts)、[contextBuilder.ts](../src/services/canvas/contextBuilder.ts)、[attachments.ts](../src/services/canvas/attachments.ts) 和 [agentMedia.ts](../src/services/canvas/agentMedia.ts)。
3. 内置文本模型判断意图并走对应分支。普通规划通过 Vercel AI SDK 和 OpenAI 兼容接口得到工具名与参数，支持 JSON 计划作为兼容回退。工具声明负责约束输出，执行发生在下一层。进入执行前，代码按用户范围清洗、去重、保护已导入剧本，区分「改词」「提炼」「重画」，并检查剧本确认及后续制作权限。见 [aiSdkAgent.ts](../src/services/canvas/aiSdkAgent.ts)、[agent.ts](../src/services/canvas/agent.ts) 和 [actionPolicy.ts](../src/services/canvas/actionPolicy.ts)。
4. runAgentLoop 保存任务摘要和调用预算，依次调工具注册表。单步会预检前置依赖，判断跳过、补依赖或失败，再执行并验收产物。执行层按工具配置超时，处理取消和结构化错误。规划器可按最新画布继续观察，或有限次重规划。它会跳过已完成目标、限制重复失败和累计调用预算。普通批量视频工具内部仍可能并发，不能仅凭外层逐项执行就认定 ComfyUI 只收到一个任务。见 [agentLoop.ts](../src/services/canvas/agentLoop.ts)、[toolRegistry.ts](../src/services/canvas/toolRegistry.ts)、[runner.ts](../src/services/canvas/runner.ts) 和 [jobs.ts](../src/services/canvas/jobs.ts)。
5. 完成后同步画布、保存项目，反馈完成、失败和后续操作。旧聊天和任务记录存于项目 agentState。它提供运行摘要，普通任务重开时不会凭摘要自动恢复提交。项目记录与制作队列彼此独立。现有 MCP 队列由 Rust 服务持久化，以项目 ID 和请求 ID 去重。

## 连续拍怎么工作

- 同一聊天面板在连续拍项目里调用 runContinuousTurn。流程自行判断规划、重排、查看状态、确认、截尾帧等意图。内置 LLM 分场估时、生成结构化计划，再检查原剧本中场次、动作、对白、说话人和时长。计划结构存实际模型、画幅、场景资产引用、各镜开头和结尾状态、音效和对白。规划随后创建画布节点，并按项目保存计划与节点映射。
- 阶段为准备资产、视频拍摄和完成。逐场确认资产，复用已有图，补齐缺图和开场图并持久化进度。全部素材通过检查后再确认拍摄。按场和段依次执行，连续镜头可读取已存的视频末帧，并按原片素材 ID 缓存尾帧；有些路径还会用视觉模型选择角色参考、做尾帧修复。换场使用新场的开场图。
- 提交前记录未确认的提交状态，拿到供应商任务 ID 后保存，恢复时有 ID 就先查询原任务。缺任务 ID 又无法确定是否已提交时，连续拍会阻止自动重提。已有结果会被识别并复用。现有 MCP 的 run_capture_node 可以调用已确认计划的节点，但缺独立的结构化计划创建、变更、场景确认、开拍确认及恢复查询入口。见 [capture.ts](../src/services/continuous/capture.ts) 和 [model.ts](../src/services/continuous/model.ts)。

## 删除聊天面板之前要剥离的调用

现有部分业务工具仍会自行请求 Dramlo 配置的文本或视觉模型。除聊天外，涉及剧本和分镜生成、H3 提示词编译及改写、连续拍规划和对白审核、视觉参考选择、尾帧续拍提示词，以及若干生成后的图像、视频和语音质检。应逐项识别调用条件和降级路径。外部方案先提供完整提示词、资产引用和审校结论，Dramlo 执行确定性校验和生成；真实媒体生成供应商继续按项目设置使用。见 [runner.ts](../src/services/canvas/runner.ts)、[storyboard.ts](../src/services/ai/storyboard.ts)、[agentMedia.ts](../src/services/canvas/agentMedia.ts) 和 [capture.ts](../src/services/continuous/capture.ts)。

## 服务迁移检查

按[产品基线的验收顺序](studio-product-goal.md#交付顺序与验收)推进。普通画布与连续拍的确定性逻辑都经过下面的运行时核对。

- **项目与配置。** Rust 本地服务保存项目和配置，写入时校验项目修订号。用测试副本验证项目、选中镜头和资产引用。
- **任务与 MCP。** stdio MCP 连接 Rust 服务，浏览器从同一服务查询状态。确认、持久队列、去重和恢复独立于浏览器标签页。
- **媒体和本机集成。** Rust 服务提供本机媒体范围读取和打开原片目录。浏览器文件选择器负责导入，服务端 FFmpeg 可提取真实尾帧。
- **节点字段与同步。** 人物节点通过 `subjectId` 读取人物卡的提示词与选用图。普通视频节点通过 `shotId` 读取镜头的终稿、时长、帧和产物，节点保留自己的布局与生成规格覆盖。普通视频节点的接入归镜头字段管理。自由视频节点持有自己的提示词、参考和产物。项目默认分辨率由节点读取时继承。修订刷新同步镜头标题、绑定边和产物状态。分镜查询的旧 `status` 响应字段由当前产物派生，进行中的状态来自服务端队列。
- **移除旧运行时。** 先让外部 Agent 在未配置 Dramlo 文本及视觉供应商的条件下，读 Skill、写结构化分镜、使用最新素材生成一镜。连续拍的计划、确认和恢复有独立入口后，移除聊天、意图路由、内部规划、自主度及专用供应商入口。保留手动制作和生成端点仍在使用的共享模块，验证当前格式项目可开、已选产物可预览。

早期设计见[方案归档](archive/early-plans.md)。

## 改造实施计划

以 Fork 的 `49f74f9` 为本轮基线。原版目录继续按上游使用。开发与回归使用隔离项目或副本，真实生成单独验收。每一阶段经过自身验收后再切换默认入口。

| 阶段 | 改造内容 | 通过条件 |
| --- | --- | --- |
| 1. 一镜制作链路 | 使用本机 Rust MCP 验证接口。补外部 Agent 的结构化分镜写入、画布同步和修订检查。再拆出确定性的一镜预检、提交、收件及原片定位，接收外部 Agent 给出的最终提示词和绑定。 | 用隔离环境验证原剧本和旧镜头保留，人工改过的镜头使用最新值，预检不产生任务。经确认后用现有 H3 工作流跑一镜，原项目可预览并定位文件。全程无需配置内置文本或视觉模型。 |
| 2. 本地服务与 Web 界面 | 保留 Vue 画布。Rust 服务依次接管项目及配置、媒体访问、任务与 MCP。由同一服务持久化修订和任务状态，UI 和 MCP 都走此服务。界面将连接诊断、默认设置、项目覆盖和当前镜头的实际配置放在可直接查看的位置。 | 用当前格式项目验证保存、重开、选片及回退。浏览器支持导入、播放和拖动进度，服务能打开原片目录；设置变更在界面和 MCP 双向可见，密钥不回传。关闭页面后任务仍可查询。 |
| 3. ComfyUI 接入和外部 Agent 上手 | 在 Dramlo MCP 中提供 ComfyUI 发现、分析和导入。先用本机路径和服务清单，区分 UI 工作流和 API 图，检查节点、权重和实际输入槽。界面显示相应工作流支持的参数。外部 Agent 设置页提供接入说明，创作 Skill 由 Agent 在 Dramlo 按需读取。 | 用现有 H3 图像和视频 API 图核对输入槽、缺项诊断与实际工作流绑定。外部 Agent 能在全新配置中接入 Dramlo 并获取指定工作流，检查和导入过程不提交生成或改写源文件。 |
| 4. 串行队列与中断恢复 | 确认关联当前计划和修订，按分镜顺序逐项提交。持久化提交状态、任务 ID 和产物归属，保存完成后才继续。连续镜头从上镜已选视频取真实尾帧，换场按独立绑定处理。暂停、停止当前及退出分别实现。 | 用两场三镜验证顺序、尾帧绑定、换场、产物归档和单镜重做。模拟失败、提交结果未知和退出重开，能查原任务且不重复提交。退出 Dramlo 不关闭共享 ComfyUI。 |
| 5. 移除内置 Agent 和旧桌面入口 | 逐项替换职责表中仍依赖内置 Agent 的路径，公开原有创作 Skill 和插件的发现、受控调用入口。移除旧聊天和规划运行时，保留手动制作。Web 与 Rust 成为默认发行形态。 | 使用自定义分镜 Skill 和已配置视频插件复验；核对外部 Agent 自身 Skill 配置和原项目。跑过启动、配置、制作、暂停、保存退出及再次启动后，更新操作手册和接入说明。 |

当前通过范围由[产品基线的验收状态](studio-product-goal.md#当前验证状态)维护。Web 队列用 Rust 持久化提交前标记、远端任务 ID 和选片引用。Rust stdio 提供工作台与 ComfyUI 发现两类工具。连续拍由外部 Agent 写入持久化执行计划，并在界面或 MCP 中确认。

# Dramlo 设计指引

更新于 2026-11-22（北京时间）。用这份指引判断一个功能该放在哪里、怎样让人和 Agent 一起使用、做到什么程度才算顺手。已确认的交付范围和版本验收以[产品目标与验收基线](studio-product-goal.md)为准。

## 1. 产品方向

Dramlo 是一套可独立手动使用、也可通过 MCP 交给外部 Agent 操作的本机短剧工作台。手动路径应能从导入或编写剧本走到分镜、出图、出片、看片和导出。需要生成时使用项目配置的本地或在线服务，手动编辑本身无需绑定 Agent 或配置额外的文本模型。

用户可以继续在熟悉的 Agent 里聊剧情、看参考、通读剧本，并沿用该平台支持的模型和套餐。Dramlo 保管项目、素材、工作流和任务状态。用户切换 Agent、关闭聊天窗口或自己接手，仍然从原项目继续。需要边聊边看时，系统分屏可把 Agent 和 Dramlo 并排，画布保留完整操作空间。

首次使用的标准是从打开到完成第一镜的实际成本。手动用户能从首页直接建项目。使用 Agent 的用户只需交给它一份可复制的接入指南，后续由同一入口发现 Dramlo 和 ComfyUI 能力，读取当前版本的工具说明和创作 Skill。设置页可重新打开引导。优先减少需要用户往返的页面、重复配置和猜测。

## 2. 界面与项目结构

首页、项目、资源库和设置使用常驻的全局导航。进入项目、画布或设置时，导航位置稳定。画布工具放在项目内容区，可按任务收起。Web 页面沿用系统浏览器的窗口控制。

工作台沿用现有布局，提供暖白和微冷黑灰两种外观。菜单和侧栏使用统一的外壳底色，画布保留独立的雾灰或近黑底色与低对比点阵。黑灰版的蓝调仅用于大面积背景，按钮、选中态和连线使用灰度。主要动作使用实底，常用工具和行内文字操作以柔和底色反馈悬停与按下。描边用于焦点、选中节点及需要明确边界的输入区。警告与失败保留可辨识的语义提示。素材库的布局另行设计。

下拉触发框与列表共用主题和交互。列表沿触发框左边缘等宽展开，有足够空间时位于下方，底部空间紧张时从上方展开。页面滚动或画布缩放时跟随触发框，移出可视区时收起。键盘可浏览、选择和退出。数字输入使用主题步进按钮，也支持方向键。设置表单在页内提示校验错误。视频播放时，指针离开播放器且没有键盘焦点或打开的菜单时，控制条淡出。悬停、键盘操作或暂停时恢复显示。

沿用现有项目流程，把分镜、画布、时间线设计成同一项目的三个视图。打开或切换视图属于查看，编辑和批量操作有明确入口。

| 视图 | 用户在这里完成什么 | 换到其他视图时带上什么 |
| --- | --- | --- |
| 分镜表 | 连读整场动作和对白，对照剧本原文，逐镜改时长、提示词和参考。 | 当前场次和镜头。可跳到同一镜的画布节点、候选素材和时间线片段。 |
| 画布 | 看参考、生成步骤、输入输出和依赖。在无素材时先搭完整骨架。 | 选中节点对应的镜头、素材和端口。拖动节点只改变画布布局。 |
| 时间线 | 连播检查、裁切、排顺序和明确换版。 | 所用素材版本及其来源镜头。换一镜后保留其他片段的素材和已做的剪辑。 |

镜头用稳定 ID 标识，镜号和播放时间码随顺序、时长派生。用户自写的镜头标题作为独立内容保留。剧本原文可通读，分镜作为可编辑的制作稿。剧情改动后标出需复核的场和镜头，方便人先看全文再处理局部。

审分镜时先看观众此刻该理解什么、动作从哪个状态开始和结束、位置和声音怎样接到下一镜，再选模型和工作流。粗剪阶段，缺成片的镜头可以用有明确标识的静帧占位，先连播判断整场节奏。占位素材和选用成片在界面及 MCP 中应有可区分的状态。

资源库提供项目视角，能查角色、场景、道具、原片及其引用。灵感库按项目收集文字、图像、视频和音频，可从项目和首页打开，也可在当前项目浏览其他项目的库。用户可把指定灵感转入正式素材并保留来源。浏览另一项目的灵感时保留当前制作上下文。

## 3. 提示词、参考图与节点

把分镜叙述、生图视觉正文和视频终稿分别显示。剧情或参考更新后，指出哪份稿子需要复核。用户可一次审阅并更新有关稿件，已经确认的手写稿由显式操作替换。格式、画幅、版式和生成参数有各自的字段。生图正文保留模型需要理解的视觉内容，例如某格要画什么。镜头号、交付要求和说明性标题留在界面或计划里。

节点内的提示词操作按以下顺序设计。

1. **从本镜组稿。** 用已有动作、对白、时长、前后镜、角色和场景事实组合成可编辑初稿。可以纯手动采用，对应原版中值得继承的镜头上下文组织能力。
2. **检查实际输入。** 界面与 MCP 复用同一套预检。展示实际工作流、参数、提示词、图片来源及送入顺序，定位缺少的素材、可能误导模型的文字，以及拍点和时长不一致的位置。
3. **润色或重写。** 外部 Agent 可提交候选稿。用户在节点内对照原稿、查看差异后采用。采用稿件、批准生成和选用产物是三个独立动作。

角色板、场景锚点、分镜看板、首帧和尾帧各有用途。生成前列出本镜实际引用的人物和图片，对明确的人物漏绑给出姓名和来源。参考图已有可辨外形时，正文重点描述动作、表演和当前变化。四格看板可按需裁出一格，裁出的单幅作为新素材，用户可预览后选为首帧。连续动作取上一镜已选视频的真实末帧，并从该末态写下一镜。换场或硬切时可断开这条依赖。

确定会提交错误输入的情况应在预检阻断，例如把四格看板整体当单幅首帧，或必填槽仍在读取模板示例图。推测性问题给可定位的提醒，例如代词或人名歧义、画幅无法识别、提示词有疑似元描述。审美和编排由创作者判断。预检有可靠报价时给预估，其他情况下至少说清这是本地 GPU 任务还是在线调用。

## 4. 配置、工作流与创作 Skill

同时显示 Dramlo 中已有的可选配置和本机发现的可导入工作流。发现后可直接查看输入、模型权重、输出和约束，并选中导入。用户准备长期管理或托管启停时再保存实例。设置应能回答全局默认、项目覆盖、镜头或节点覆盖最终生效的是哪一套。检查、保存配置和实际试跑分别反馈。

以工作流实际接口决定可用模式。例如单参考槽可以是角色或场景参考。它是否接受首帧，由图的真实接线和绑定决定。槽位角色、顺序、必填及缺位策略要可查看。允许替换指定节点的模型、步数和随机种子时，优先使用局部参数覆盖，保留用户的原始 ComfyUI 工作流。

MCP 的工具描述说明字段、状态、约束和下一步行动。接入指南负责连接和入口发现。创作 Skill 分编剧、分镜、资产、生图、视频等阶段，说明怎样创作并用案例消除歧义。外部 Agent 按需从 Dramlo 读取最新版 Skill，技能只维护一份。扩展库和自定义节点沿用[扩展规范](studio-extension-library.md)，参数和端口应能从界面与 MCP 查到，安装来源和运行结果可追溯。

### 按任务发现 MCP 工具

首批已实现普通镜头绑定和精简接入。新接入默认常驻 `studio_web_status`、`studio_project`、`studio_pending_jobs`、`studio_find` 和 `studio_call`。设置里的外部 Agent 接入只需提供一个 Dramlo MCP，ComfyUI 的检测、工作流读取与导入也通过该入口发现。配置导入后返回 Dramlo 配置 ID，供镜头预检直接使用。客户端覆盖与验收状态见[产品基线](studio-product-goal.md#当前验证状态)。

工具目录按剧本分镜、画布素材、生图出片、剪辑导出、ComfyUI 与模型设置、扩展维护组织。查找支持按目标跨组匹配，默认只返回少量名称和简述，可在同一次查找展开指定动作的完整定义。每个动作维护一份参数契约，指南负责多步操作顺序。项目和画布先返回摘要，支持按镜头读取。ComfyUI 先返回实例、工作流与槽位概要，再按需读取完整 API 图。

精简连接在本机 Web 服务尚未启动时也能查到并调用 `studio_start_web`。stdio 自身处理的动作与转交 Web 服务的动作由同一目录区分。按名调用须按原操作定义校验内层参数，并验证精简和原生调用的结果、错误与确认行为一致。Web 服务已联机时，以该服务实际可用的定义为准。

「把这镜交给 Agent」首版从用户正在操作的页面明确传递项目与镜头或节点 ID。Agent 执行前读回目标及修订。若用户没有交出目标，按镜号或明确对象定位。项目概况现有接口只读取本地项目状态，浏览器临时选区需另行交接。

精简模式使用固定的小清单，按名调用沿用原工具的参数约束、结果和操作确认。完整模式保留供现有脚本与需要全部原生工具的接入使用。具备工具列表刷新能力的客户端可以试点会话内切换原生工具组，每次替换当前组。先实测客户端是否刷新工具列表并缩小模型实际收到的工具集，再确定是否推荐使用动态模式。第二批统一生成预检时接入生成组，复用已有预检、确认与恢复链路。

首轮以五项常驻、初始工具描述与参数定义序列化体积在完整模式的 15% 以内为目标。在 Codex、Claude Code、WorkBuddy 比较精简模式和客户端支持的原生延迟加载，记录空白会话和任务全过程的可观测上下文、调用次数及成功率。验收任务为换绑并读回，以及单独注册 Dramlo MCP 后检测 ComfyUI、导入工作流并预检当前镜头。原脚本用完整模式回归。独立画布入口等高频任务的实测结果再决定。

参考 [AWS MCP 的操作查找与按名调用](https://docs.aws.amazon.com/pdfs/aws-mcp/latest/userguide/mcp-ug.pdf)、[Figma 的选区概要与按节点展开](https://developers.figma.com/docs/figma-mcp-server/tools-and-prompts/#get_metadata)、[GitHub 的原生工具集选择](https://github.com/github/github-mcp-server#specifying-toolsets)和 [Cloudflare 的结果体积控制](https://github.com/cloudflare/mcp)。

### 按制作任务读取 Skill

Dramlo 维护创作 Skill 正文和参考资料。外部 Agent 通过同一个 MCP 查找和读取本次制作所需内容，作用范围是本次指定的项目、工序和对象。接入时只提供简短使用指引。按阶段查到匹配项后读主文，再按需读取参考。换绑、查询状态等纯操作直接按工具说明执行。Dramlo 的接入流程不向外部 Agent 的技能库、配置或工作区写入 Skill。

操作顺序继续由操作手册维护，`studio_get_guide` 从手册按章节返回。精简目录按需要揭示相关章节，避免先读整章接入说明。通用创作 Skill 负责跨平台的创作判断，Dramlo 专属创作 Skill 负责把创作决定落实到项目稿件和输入。接入与 ComfyUI 指导 Skill 指向操作手册和工具定义。

现有 `studio_list_skills` 和 `studio_read_skill` 作为首版入口，纳入精简目录发现。后续可按任务或工序筛选目录，返回稳定 ID、来源、版本和适用范围。长手册先给章节索引，按需读取相关章节。续做时用 ID、版本和引用路径复核所用资料。涉及脚本或其他可执行附件时，通过 Dramlo 已配置的业务工具执行相应操作。

验收用同一客户端测试制作任务和无关任务。制作任务能只读当前工序所需资料并完成交付，未安装副本。无关任务不触发读取。若用户在同一会话切换目标，Dramlo 创作指引随原任务结束适用范围，客户端已读取的正文仍可留在该会话历史里。

## 5. 执行、版本与换手

- **先准备，再运行。** 剧本、分镜、提示词、素材占位、节点与依赖可一起保存。画布和 Agent 都能区分未连接、等待指定上游、缺配置或必填输入、可以提交。判断来自实际工作流和素材状态，画布连线同时承担解释作用。
- **一次确认，串行完成。** 用户可亲自启动，或明确授权 Agent 监督。按计划依赖和镜头顺序逐项提交，当前结果归档后再推进；暂停默认仅停止后续提交。失败或结果未知时保留现场和原任务标识，查清后继续，已完成项可直接复用。创作准备阶段可连续执行日常编辑。任务成功表示产物已归档，审片通过由选用状态表示。某步需要上一镜已选成片时，按初次确认的计划沿用已定的选择规则。需要人工挑选时，停在该依赖并定位到候选。
- **人和 Agent 看见同一份变更。** 标出改了哪个镜头、参考或配置。预检使用最新数据，执行确认重点核对实际影响提交的输入。其他编辑可继续进行。用户手动修改了相关输入时，显示差异并更新计划。
- **选片和剪辑各有明确版本。** 每次生成进入候选，能看到来源、原片路径及在项目中的用途。时间线按确定的素材版本引用。从候选选为当前镜头版本后，需要用户明确选择才换入粗剪。依赖旧尾帧的后继镜头标记复核，其他镜头可继续使用现有素材。
- **运行状态可找回。** 项目重开可查已完成、当前项、阻塞原因和可继续的动作。退出 Dramlo 与停止独立 ComfyUI 分开。导出显示使用的时间线版本和产物位置，时间线变化后旧片仍可定位，并提示是否对应当前剪辑。

## 6. 改进顺序与验收样例

此前已实测零产出搭计划、镜头产物归档、工作流发现及基础硬切导出。以下是从这些能力出发的体验设计，整体的手动、Agent 与交接体验要分别验收。具体交付状态见[产品基线](studio-product-goal.md#当前验证状态)。

| 次序 | 改进目标 | 验收重点 |
| --- | --- | --- |
| 1 | 打通分镜、素材、画布、时间线定位。把确定的素材版本写入粗剪引用。 | 进入或切回页面可找到同一镜。重排、打开剪辑页或重做一镜时，旧片段维持原剪辑引用。 |
| 2 | 完善连续审稿、节点内组稿与检查、生成输入预览。 | 关闭外部 Agent 后仍能完成三镜。用户能在同一处判断这一镜用什么图、怎么生成、改动影响谁。 |
| 3 | 核对 MCP 和界面的双向交接。用同一套能力呈现实际配置、输入、任务与失败原因。 | 从两种入口预检同一镜，工作流、参考顺序、最终提示词和阻塞原因一致。另一方改完即可读到新值。 |
| 4 | 完善连播、选片、恢复和导出，再按需求扩展灵感库和插件。 | 换一镜进入粗剪可保留既有裁切。中途关闭后，能定位任务并继续。粗剪中能检查一条全段 BGM，具体导出能力按目标版本验收。 |

同一段两场三镜，分别用纯手动、纯外部 Agent 和中途换手跑三遍。

1. 导入剧本，在零产出时搭好三镜和依赖。第 1 镜用角色与场景参考；第 2 镜接第 1 镜选中成片的真实尾帧；第 3 镜换场，接自己的场景参考。
2. 在界面手动改第 2 镜动作或参考，核对预检中的实际输入。换手场景让 Agent 读回这次修改，用户再在界面看到 Agent 写入的状态。
3. 一次批准，核对任务逐项提交和归档。模拟失败、重开项目或 Agent 重连，确认可以从当前项继续。给使用同一场景的镜头复用素材。
4. 在时间线先用标识清楚的静帧占位连播，再看片核对第 2 镜是否从前镜末态继续、动作和声音是否接得上。重做第 2 镜，先留候选，再明确替换剪辑中的这一段，核对第 1、3 镜、已有裁切和旧片定位。

## 7. 如何持续维护

新的想法补到相应章节，写清实际遇到的操作、造成的影响、拟改的行为和验收方法。新证据改变判断时，更新原段落。确认了产品范围或优先级就同步到[产品基线](studio-product-goal.md)，上线后的具体操作进[操作手册](studio-operation-manual.md)，真实使用故事和宣传素材进[产品故事](studio-origin-and-user-experience.md)。

平台设计采纳创作资料中的可复用原则。模型专项经验按证据使用，记录对应工作流、版本和验证条件。社区个案用于选择回归场景，本机验证后再决定是否形成产品约束。

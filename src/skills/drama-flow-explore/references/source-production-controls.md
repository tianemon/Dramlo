# 媒体制作与 ComfyUI 串行适配

先汇总将要实际提交的顺序、输入、引用图的用途、版本、工作流、模型、服务位置、预计消耗和要回收的文件。未知的消耗写未知。如果用户批准的就是这份具体计划，一次批准对本计划生效。改动内容、目标服务或费用范围时明确受影响项。只求提示词、预算或清单时，交付到该处。

使用本地 ComfyUI 时读取[串行适配](references/ComfyUI.md)。其他生成器须从当前工具或接口文档查实提交、状态与收件机制。维护同一计划唯一的运行记录。一个资产从提交到终态、收回、核实后才推进下一个。模型输出异常、收件失败、历史对不上时停在当前项，保留证据供恢复。

若通过剧流等共享画布写入，先按项目 ID、镜号和修订定位。保存提示词或选片前重读目标，接口支持时带上读到的修订值（剧流为 `expectedUpdatedAt`）。遇到版本冲突，保留人工改动，重新对齐本次要改的字段。断线后用已存请求 ID 或远端任务 ID 查在途工作。下载到的新 take 先登记为候选，换选后复核[依赖它的续镜](../studio-hub/references/交接与变更.md)。

回收时记录任务 ID、素材 ID、源镜号、模型/工作流版本、真实文件位置、字节指纹、可用片段与返修项。先确认可打开，再看画面中身份、手和持物、核心字、口型及终点动作。计划已存、生成成功、收件完成、艺术上可用是不同状态。不能实际联网或缺模型时，只报告已完成的计划和具体缺口。
````

# 制片、实验与质量门

## 制作记录最小集合

- 项目：成片画幅、交付对象、不可打破的设定、计划时长与许可。
- 场序：地点、时段、人物在场名单、上一场结束事实、本场发生的变化。
- 镜头：稳定 ID、依赖、镜位、资产版本、技术设置、验收标准、失败时的备用方案。
- 素材：可打开的实际文件、来源、使用范围、版本与接受状态；哪个被用进时间线，要能反查。
- 渲染任务：排队/执行/成功待验/通过/失败/取消，实际任务 ID、输出位置和错误分类。变更应产生新版本，不覆盖已批准素材。

**一次批准不等于把一批全提交。** 如设备一次只承载一个任务，外层队列按剧本顺序逐项提交。依赖上一个镜头尾帧的任务，须等上一个输出能打开且被接受，再从确切的版本提取。失败先区分未接单与状态未知，查询后再决定重试，避免重复占资源。保存哪一条用了哪个输入；暂停时保留已完成项。

## 质量门

| 门 | 不通过就暂停什么 |
|---|---|
| G0 故事确认 | 人物动机、因果或关键信息不对，不进分镜 |
| G1 分镜与关系锁定 | 方向、站位、人数或道具不清楚，不进正式生成 |
| G2 关键资产验收 | 身份、重要物件或构图不稳，不跨镜复用 |
| G3 镜头审片 | 角色漂移、做错事、音画错位，先试剪法或只替换当前镜 |
| G4 粗剪 | 无法理解整场，不上线精修与超分 |
| G5 交付 | 硬错误、平台不兼容、授权不清楚，不发布 |

## 实验要回答一个问题

同一规格固定参考、时间、分辨率、模型、工作流版本、seed 和主要采样参数；一次改一个变量，至少挑典型镜头与困难镜头各一个，需判断稳定性时用多个固定种子重复。按镜分别记录人物、动作、构图、声音和耗时；不拿单条最好看的结果当成功率。比较速度时记录冷/热启动、失败率和**每分钟可用素材**。讨论画质时先说明是静帧纹理、运动连续还是身份识别。

**返工顺序**：先修接线和输入事实，再修表达/导演决策，最后才换模型、量化或叠加后处理。先定位最早的错误，比反复要求「更高清更精致」便宜。
````
